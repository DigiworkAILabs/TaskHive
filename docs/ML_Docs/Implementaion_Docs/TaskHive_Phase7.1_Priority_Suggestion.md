### Deliverable
When Admin creates a task, a "Suggest Priority" button appears next to the Priority dropdown. On click, ML predicts priority with confidence score. Admin can accept or ignore — fully non-blocking. If ML server is down, fallback returns MEDIUM silently.

## Synthetic Data

**File:** `training/data/priority_data.csv`

**Columns:** `title, description, tags_count, estimated_hours, emp_completion_rate, emp_avg_hours, priority`

**Generation logic (`training/training_generator/generate_priority_data.py`):**
- CRITICAL → titles containing: urgent, critical, production down, blocker, outage
- HIGH → titles containing: bug, fix, crash, broken, error, important
- MEDIUM → titles containing: update, improve, enhance, feature, change
- LOW → titles containing: docs, documentation, minor, cleanup, refactor
- Add random noise (15%) to avoid perfect separation
- emp_completion_rate: random 0.4–1.0
- emp_avg_hours: random 1–12

---

## Model

**Algorithm:** Random Forest Classifier (scikit-learn)
**Features:** title_tfidf (50 features) + description_tfidf (30 features) + estimated_hours + tags_count + emp_completion_rate + emp_avg_hours
**Target:** priority (0=LOW, 1=MEDIUM, 2=HIGH, 3=CRITICAL)
**Train script:** `training/scripts/train_priority.py`
**Output:** `inference-server/artifacts/priority_model.pkl`
