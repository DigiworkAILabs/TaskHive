## ⚠️ Platform-Critical Rules — Read Before Writing Any Code

### Rule 1: Never Import `dart:io` at Top Level
`dart:io` does not exist on Web. Importing it at the top of any file that is also compiled for Web will cause a **compile error on `flutter build web`**, even if the import is only used inside an `if (!kIsWeb)` block. Dart compiles the entire file.

**Always use conditional imports:**
```dart
// In any file that needs dart:io on native but not on web:
import 'cookie_jar_helper_stub.dart'
    if (dart.library.io) 'cookie_jar_helper_native.dart';
```

### Rule 2: `flutter_secure_storage` Platform Behaviour
| Platform | Storage Backend | Notes |
|----------|----------------|-------|
| Android | EncryptedSharedPreferences | Requires `encryptedSharedPreferences: true` in AndroidOptions |
| iOS | Keychain | Works out of the box |
| macOS | Keychain | Works out of the box |
| Windows | Windows Credential Manager | Works out of the box |
| Linux | libsecret | Requires `libsecret-1-dev` on build machine |
| Web | localStorage (AES encrypted) | XSS risk — acceptable for non-JWT data (user info only) |

### Rule 3: macOS Network Entitlement — Without This, ALL API Calls Fail Silently
macOS Flutter apps are sandboxed. Without the network client entitlement, every HTTP request silently fails with no error. See entitlement files below.

### Rule 4: Windows/Linux — No Special Config Needed for HTTP
Dio works on Windows and Linux without extra configuration.

### Rule 5: Web CORS
The backend must allow `http://localhost:PORT` (or the web dev URL) in its CORS config. The `withCredentials` equivalent in Flutter Web is handled automatically by the browser when cookies are set by the server with correct CORS headers (`Access-Control-Allow-Origin` must be explicit, NOT `*`, when `allowCredentials=true`).

### Rule 6: `PersistCookieJar` vs `DefaultCookieJar`
- **Native (Android/iOS/macOS/Windows/Linux)**: Use `PersistCookieJar` with `FileStorage` — cookies survive app restarts
- **Web**: Cookies are managed by the browser natively. Use `DefaultCookieJar` (in-memory) — the browser handles persistence automatically via `Set-Cookie` headers
- This split MUST be done via **conditional imports**, not `kIsWeb` runtime checks

### Rule 7: Code Generation Order
Always run in this order:
```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze
```
Never skip step 2. Generated files (`.freezed.dart`, `.g.dart`) must exist before compiling.

### Rule 8: Do NOT Mix `@riverpod` Annotation and Manual `StateNotifierProvider`
`AuthNotifier` uses manual `StateNotifierProvider` (not `@riverpod` annotation) because it needs to call `restoreSession()` in its constructor. Do not add `@riverpod` annotation to `AuthNotifier` — it will conflict with the manual provider declaration.

## ★ Conditional Import Pattern for dart:io (Platform-Safe Cookie Jar)

This is the correct way to handle the `PersistCookieJar` vs `DefaultCookieJar` split without breaking Web compilation.

### lib/core/network/dio_client.dart (the import switch)

```dart
import 'package:cookie_jar/cookie_jar.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

// Conditional import — Dart compiler only includes the relevant file
import 'cookie_jar_factory_stub.dart'
    if (dart.library.io) 'cookie_jar_factory_native.dart'
    if (dart.library.html) 'cookie_jar_factory_web.dart';

export 'cookie_jar_factory_stub.dart'
    if (dart.library.io) 'cookie_jar_factory_native.dart'
    if (dart.library.html) 'cookie_jar_factory_web.dart';
```

### lib/core/network/cookie_jar_factory_stub.dart (fallback)

```dart
import 'package:cookie_jar/cookie_jar.dart';

// Stub — never actually called. Satisfies Dart's static analysis.
Future<CookieJar> createCookieJar() async {
  return DefaultCookieJar();
}
```

### lib/core/network/cookie_jar_factory_native.dart (Android/iOS/macOS/Windows/Linux)

```dart
import 'dart:io';
import 'package:cookie_jar/cookie_jar.dart';
import 'package:path_provider/path_provider.dart';

Future<CookieJar> createCookieJar() async {
  final appDocDir = await getApplicationDocumentsDirectory();
  final cookiePath = '${appDocDir.path}/.cookies/';
  // Ensure the directory exists
  await Directory(cookiePath).create(recursive: true);
  return PersistCookieJar(
    ignoreExpires: false,
    storage: FileStorage(cookiePath),
  );
}
```

### lib/core/network/cookie_jar_factory_web.dart (Web)

```dart
import 'package:cookie_jar/cookie_jar.dart';

// On web, the browser manages cookies via Set-Cookie headers automatically.
// DefaultCookieJar acts as a pass-through — no dart:io needed.
Future<CookieJar> createCookieJar() async {
  return DefaultCookieJar();
}
```

## ★ Riverpod Architecture Rules (Enforced Across All Phases)

| Rule | Detail |
|------|--------|
| Use `StateNotifierProvider` for `AuthNotifier` | It needs `restoreSession()` in constructor — `@riverpod` annotation does not support this pattern |
| Use `@riverpod` annotation for all other providers | Cleaner code generation via `riverpod_generator` |
| Use `AsyncNotifierProvider` for providers that do async init | e.g. EmployeeListNotifier loads on first build |
| Use `ref.watch` in `build()` | Never in constructors, initState, or callbacks |
| Use `ref.read` in event handlers | Callbacks, button taps — never `ref.watch` |
| Use `ref.listen` for side effects | Snackbars, navigation triggers — in `build()` only |
| `authStateNotifierProvider` is the single auth truth | All role checks, redirect logic, user info derive from this |

## ★ GoRouter Rules (go_router v14)

| Rule | Detail |
|------|--------|
| Use `StatefulShellRoute.indexedStack` | NOT the old `ShellRoute` — breaking change in v14 |
| Router redirect returns `null` when `isLoading == true` | Shows splash — prevents login flash |
| Router only reads auth state via `ref.read` in redirect | `ref.watch` in redirect causes infinite redirect loops |
| Use `ValueNotifier` + `refreshListenable` | The correct way to trigger router refresh on auth state changes |
| All deeplink routes use `state.uri.queryParameters` | NOT `state.queryParams` (removed in v14) |

## Offline Caching Strategy (All Phases)

**Library**: `hive_flutter`
**Pattern**: Cache-then-Network (stale-while-revalidate)

```
On provider load:
  1. Immediately emit Hive cached data → UI shows instantly
  2. Fire API request in background
  3. On API success → update Hive box + update state → UI refreshes silently
  4. On API failure + cache exists → keep showing cache, show offline banner
  5. On API failure + no cache → show error state

On logout:
  → CacheService.clearAll() — wipes ALL Hive boxes
```

| Hive Box | Content | Phase |
|----------|---------|-------|
| `employees_box` | List of serialized EmployeeModel | 2 |
| `tasks_box` | List of serialized TaskModel (admin view) | 3 |
| `my_tasks_box` | List of serialized TaskModel (employee view) | 3 |
| `notifications_box` | List of serialized NotificationModel | 4 |
| `analytics_box` | Serialized dashboard stats map | 6 |

> Auth data is NEVER cached in Hive. User info → SecureStorageService. JWT → CookieJar.
